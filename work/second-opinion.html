Second Opinion

A 5-agent healthcare AI verifier loop — three specialists in parallel, a synthesizer, and a verifier that fact-checks every claim against a 52-source clinical corpus before output.

Repo → Architecture (README)
Status
Shipped at Cerebral Valley × Anthropic hackathon, April 2026 · Open source
Role
Solo build — architecture, agents, corpus curation, UI
Audience
Clinical staff handing off a complex chronic-condition patient
Stack
Next.js 16, React 19, Anthropic SDK, Claude Opus 4.7, prompt caching, NDJSON streaming

The problem

A patient walks into a specialist appointment with a chronic, multi-system condition. The clinician has 12 minutes. The chart is 40 pages. Most of what matters is buried in clinical notes the patient never saw and didn't write.

Generic LLM "summarize this chart" prompts confidently invent supporting evidence, paraphrase clinical guidelines into something subtly wrong, and never tell the clinician when they're uncertain. In healthcare, that failure mode isn't acceptable. The system needs to be honest about what it doesn't know.

Three specialists in parallel, not sequential

Sequential agent chains feel architecturally clean but kill latency. Parallel calls cost N× tokens but ~1× wall-clock time. With prompt caching on the corpus, the marginal cost is small. With sequential chains, you're paying N× time — which kills the demo and any real-time use case.

The verifier reads the corpus, not the synthesizer

Critical. If the verifier just re-reads the synthesizer's output and asks "does this sound right?", it's a glorified hallucination check. The verifier has to do its own retrieval against the same ground-truth corpus the specialists drew from, and confirm every load-bearing claim is supported.

The verdict gate

  • GREEN — every claim is supported in the corpus. Ship to user.
  • YELLOW — most claims supported, one or two are inferential. Ship with the inferential claim flagged inline and a "Verify this" CTA.
  • RED — a claim contradicts the corpus, or the verifier can't find supporting evidence for a high-stakes claim. Do not ship. Surface "We can't safely answer this — escalate to a clinician."

Key decisions + gotchas

Prompt caching makes the economics work

Five agents per request, each reading the 32.5K-token clinical corpus, would be unviable without Anthropic's prompt caching. With cache_control: { type: "ephemeral" } on the corpus block:

  • Input tokens (uncached): ~32.5K × full rate
  • Input tokens (cached): ~32.5K × ~10% of full rate
  • Practical cost: difference between ~$0.50/request and ~$0.05/request at production volume
Gotcha: the cached block must be at the top of the messages array. Put user input above the corpus and you invalidate the cache on every request. Ephemeral cache TTL is ~5 minutes — plan for it.

The first verifier I built was useless

Same model, same corpus access, slightly different system prompt. It kept agreeing with the synthesizer because they were thinking about it the same way. Fix: change the prompt frame to adversarial — "find the weakest claim, find the unsourced claim, find the contradiction." Different mode, same model, much better verifier.

YELLOW state has to look visibly different

Without a different visual treatment, clinicians habituate to ignoring the verdict. The YELLOW inferred-claim inline flag has to be unmissable but not alarmist; the RED block has to feel like a hard stop, not a suggestion.

Outcomes

  • Shipped at Cerebral Valley × Anthropic "Built with Claude Opus 4.7" hackathon, April 2026 — open source.
  • Latency: parallel architecture cut end-to-end response from ~22s (sequential) to ~7s.
  • Cost: prompt caching delivered ~90% input-cost reduction on warm calls.
  • Corpus built initially for adenomyosis — expanding to fibroids, endometriosis, Hashimoto's, long COVID, lupus, POTS.

What I'd build next

  • Claim-level citation linkage. Each claim in the brief becomes a clickable link to the source paragraph, with the verifier's confidence score inline.
  • Specialist routing, not parallel-all. A router model picks the right 2–3 specialists per chart instead of always running all three. Cuts cost and latency further.
  • Real eval suite. Today the only eval is "Claude verifies Claude." In production: a labeled dataset where domain experts mark claims as supported / unsupported, and the verifier's GREEN/YELLOW/RED verdicts are scored against the labels weekly.
  • Cross-corpus checking. A 52-source corpus is a beachhead, not a foundation. Production pulls from current clinical guidelines + peer-reviewed updates; verifier detects corpus staleness.
